# SPS 日程互通（2026-10-30）

正式前端与现有数据库保持原位。新增 `/api/integrations/sps` 仅接受共享服务密钥和配置中明确的 `SPS_CLUB_ID`，保存 SPS 源活动与单调版本；不修改手动预约和课程。`SPS_SYNC_KEY` 只存 Cloudflare Secret，不提交。

来源活动包含任务 ID、标题、开始/结束时间和地点，不包含负责人、账号、任务说明或完成记录。未设置地点显示“未定”；固定归类 SPS。日期窗口读取时按北京时间拆分跨日活动，日末可用24:00，午夜结束不占下一日。窗口外活动保留源数据，随后自然进入两个月日历。无需为远期活动建立额外定时器。

SPS 端负责原子排队与后台重试。接收端保留原 `booking_state` 中的手动记录、课表和其他字段；旧版本和相同版本重复请求不会改变状态或再发通知。源快照变更会增加预约 revision，现有 WebSocket 通知客户端读取。SPS 任务修改/归档/恢复同步更新或撤下对应块。

同步块在预约页详情中显示来源，并链接 SPS 原任务；普通取消接口拒绝同步块。其他手动活动的新增/取消权限保持原样；新增预约的同社团重复、跨社团确认检查也包含同步块。SPS 已发布任务按源状态同步展示，允许重叠，不以预约页交互校验阻断源日程保存。

新增公开只读 `/api/activities`，仅返回当前公开日期窗口内的活动字段，不包含课程；供 SPS 日历展示其他社团安排。SPS 前端过滤 SPS 类别以避免重复。

验证：74项 Node 测试、TypeScript、12项 SQL 冲突检查，Pages/两个本地 HTML 导出成功。本地真实 Worker 与 SPS Worker 互通，页面新建活动经后台队列自动出现在预约页，社团、时间和地点一致；来源详情无取消按钮。生产部署回执与线上无损比对保存在 SPS 项目的 qa 文档，临时凭据不进入仓库。

维护仍用 `npm run deploy` 仅发布 `wrangler.leafuke.jsonc` 后端；`npm run build:pages` 生成 Pages 前端。不要向 Worker 上传静态站点，不重建 `club-booking-production`，不回写原 uniCloud/D1。导出脚本额外允许显式 localhost HTTP 地址用于联调，生产默认仍是 HTTPS 自定义域名。
